# v1.1 — Fonte sem SCPI cru nos experimentos + `mestre.py` orientado a objetos

Este documento cobre o que mudou da v1.0 (`CHANGELOG/v1.0.md`) para cá. A
v1.0 já tinha os dois ORMs e a separação `experimentos_nativos/` /
`experimentos_waveform/`; esta versão termina o que ficou pela metade nesses
dois pontos.

## 1. Por que mudar

1. Sete arquivos de `experimentos_nativos/` (`01`, `02`, `03`, `04`, `05`,
   `18`, `19`) chamavam `fonte.write("VOLTage:MODE PULSe")` e afins
   diretamente — texto SCPI cru dentro do experimento, quebrando a garantia
   de segurança que o resto do ORM já tinha (as *properties* `voltage`,
   `frequency`, `current_limit` validam contra `max_voltage_rms`/`max_peak_v`;
   esses sete arquivos não passavam por nenhuma validação).
2. `mestre.py` era só funções soltas (`inicializar_instrumentos()`,
   `executar_experimento()`, `main()`). Cada `experimentos_*/NN.py` recebia
   `run(fonte, osc, config)` como 3 parâmetros sem nenhuma relação de herança
   com `mestre.py` — não era possível instanciar/herdar a bancada como
   objeto.
3. Consequência de resolver (2): ficou óbvio que `experimentos_nativos/comum.py`
   e `experimentos_waveform/comum.py` duplicavam literalmente `salvar_classe`,
   `janela`, `ruido_awgn`, `snr_medida` e `_validar_captura`.

## 2. `ametek_orm.py` — métodos semânticos em vez de `.write()` cru

Novos métodos em `AmetekMX30`, todos validando contra os limites de
segurança já existentes (do mesmo jeito que o setter `voltage` já fazia):

- `trigger_step(voltage_rms)` — `VOLTage:MODE STEP` + `VOLTage:TRIGgered`
- `trigger_pulse(voltage_rms, width_s=...)` — `VOLTage:MODE PULSe` + `VOLTage:TRIGgered` + `PULSe:WIDTh`
- `configure_harmonics_csine(thd_pct)` — `SOURce:FUNCtion:SHAPe:CSINusoid` + `SHAPe CSINe`, validado contra a nova constante `AmetekMX30.MAX_CSINE_THD_PCT` (20%)
- `frequency_drift_list(start_hz, end_hz, voltage_rms=..., dwell_s=...)` — sequência `LIST:FREQuency`/`LIST:VOLTage`/`LIST:DWELl`/...
- `enable_dc_offset(offset_v, ac_peak_v=...)` — `SOURce:MODE ACDC` + `SOURce:VOLTage:OFFSet`, validando **offset + pico AC combinados** contra `max_peak_v` (validação que não existia antes: a classe 19/DC_OFFSET podia, em tese, somar offset + pico AC acima do limite físico sem que nada acusasse)

`write()`/`query()` continuam existindo (uso interno desses métodos, e de
`preflight.py`/testes) — só deixaram de ser chamados de dentro de arquivo de
experimento.

## 3. `sinais.py` (novo) — matemática de sinal sem duplicação

`janela`, `onda_com_harmonicos`, `aplicar_entalhes`, `oscilacao_amortecida`,
`ruido_awgn`, `snr_medida`, `tempo(config)` — tudo que os dois `comum.py`
duplicavam e não dependia de config/fonte foi para cá. Um único módulo,
importado por quem precisar.

## 4. `mestre.py` — classes em vez de funções soltas

- **`Bancada`**: encapsula `fonte`/`osc`/`config`. `Bancada.from_env(...)`
  substitui `inicializar_instrumentos()`; é um *context manager*
  (`with Bancada.from_env() as bancada:`) que garante `shutdown()`
  (desconectar fonte/fechar osciloscópio) mesmo se a bateria falhar no meio —
  antes isso era um `try/finally` solto em `main()`.
- **`ExperimentoBase`** (`abc.ABC`): base de toda classe de distúrbio.
  Recebe a `Bancada` no `__init__` e expõe `self.fonte`/`self.osc`/`self.config`
  como atributos próprios. `executar()` é o laço genérico (capturas, AWGN,
  gravação) que unifica os antigos `executar_classe_nativa`/`executar_classe_waveform`.
- **`ExperimentoNativo`** / **`ExperimentoWaveform`**: as duas subclasses,
  cada uma implementando `_capturar_real()` do jeito que já fazia sentido
  para seu mecanismo (nativo: `configurar()` + `fonte.arm()`, com desvio
  opcional para TRACe via `usar_trace()`; waveform: sempre
  `gerar()` + `program_capture()` + `arm_transient()`).

Cada `experimentos_nativos/NN.py` e `experimentos_waveform/NN.py` agora
define uma classe chamada `Experimento` (convenção fixa, análoga a
`class Migration` do Django), herdando de `ExperimentoNativo` ou
`ExperimentoWaveform` e implementando só `gerar()` (+ `configurar()` para
nativos). `Bancada.executar_experimento()` carrega o módulo e faz
`module.Experimento(self).executar()`.

**Import de `mestre` dentro de `NN.py` sem repetir o medo de import circular
da v1.0:** antes, `python mestre.py` rodava o arquivo como `__main__`
enquanto carregava os `NN.py` dinamicamente — um `NN.py` fazendo
`import mestre` nesse momento reexecutaria o arquivo inteiro sob outro nome
de módulo. Correção: o guard final agora é

```python
if __name__ == "__main__":
    import mestre
    sys.exit(mestre.main())
```

o que força o processo a importar o arquivo como módulo `"mestre"` de
verdade (fica em `sys.modules`) mesmo quando invocado diretamente; qualquer
`NN.py` que fizer `import mestre` depois disso reaproveita o módulo já
carregado. `preflight.py` (que já fazia `from mestre import ...` como
processo separado) não precisou desse ajuste — só passou a usar
`Bancada.from_env()` no lugar de `inicializar_instrumentos()`.

## 5. Arquivos removidos

- `experimentos_nativos/comum.py`
- `experimentos_waveform/comum.py`

Tudo que tinham virou `sinais.py` (matemática) ou métodos da hierarquia
`ExperimentoBase`/`ExperimentoNativo`/`ExperimentoWaveform` em `mestre.py`
(execução genérica).

## 6. O que **não** mudou

- Os parâmetros físicos de cada classe (níveis de sag/swell, THD, faixas de
  frequência, offsets) são idênticos — só a forma (função solta → método de
  classe) mudou. Verificado rodando a bateria simulada completa
  (`SIM_CAPTURES_PER_CLASS` reduzido) e comparando forma/shape dos `.npz`
  contra o formato anterior.
- O formato de saída (`resultados/snr_XXdb/*.npz` + `resultados/metadata/*.jsonl`)
  não mudou.
- `tests/test_offline.py` cobre a mesma superfície de antes, mais os testes
  novos para os métodos semânticos do `ametek_orm.py`.
